    Documentation

    Every feature in Elune M2, grouped by where you find it in Blender, with the steps to use it.

    Getting started

    Install the add-on and learn where its tools live.

    Requirements

    • Blender 5.0 or newer. The add-on is packaged as a Blender extension.
    • Model files extracted from the game: the .m2 plus the files that sit beside it (.skin, and for modern characters .skel and .anim). Keep them in the same folder with their original names so the importer finds them.

    Install

    1. Download the add-on .zip. Do not unzip it.
    2. In Blender open Edit › Preferences › Get Extensions.
    3. Open the drop-down arrow in the top-right corner and choose Install from Disk…, then pick the zip.
    4. Make sure Elune M2 is ticked in the Add-ons list.

    Importing a model

    Bring an M2 into Blender as editable meshes, an armature, actions and helper objects.

    Basic import

    1. Choose File › Import › WoW Model (.m2). You can select several files at once.
    2. Leave Expansion on Auto-detect unless a file is misread.
    3. Adjust the options in the right-hand column (below), then click Import M2.

    The status bar reports the detected format, vertex and triangle counts, and how many animations and attachments were built. If it says no skin file found, the .skin is missing from the folder and the mesh will be empty.

    Import options

    OptionDefaultWhat it does
    ExpansionAuto-detectWhich parser reads the file. Override only if auto-detect guesses wrong.
    Import SkeletonOnBuilds an armature from the bones and skins the mesh to it. Animations, attachments and cameras need this.
    Split GeosetsOnEach geoset becomes its own mesh object named …_geoset_NNNN. Turn off for one merged mesh.
    Import AnimationsOnCreates one Blender Action per animation sequence.
    Import AttachmentsOnCreates an empty at each attachment point (weapon and effect mounts), parented to its bone.
    Import CamerasOnCreates a Blender camera for each M2 camera (portrait, character info) with its target, field of view and animation.
    Import Bounding BoxOnCreates the editable M2_BoundingBox wireframe. See Bounding box.
    Import EventsOnCreates an empty per event ($SHR, $FL0, …) and adds standard events the model lacks so sheathe, footstep, cast and breath triggers fire in game.
    Bone Tilt (deg)0Fans bones outward so they are easier to see and click. Animations are converted in and out automatically.
    Weld Seam VerticesOnMerges the duplicate vertices M2 stores along UV and normal seams into a connected mesh. Turn off only for the in-place vertex patch, which needs identical topology.
    Animation FPS30Frame rate used to convert millisecond keyframe times to frames.
    Max Animations0 (all)Caps how many clips are built. Characters can have 400+ sequences; lower this for a quick import.
    Mirror XOffFlips handedness. If you use it, use the same setting on export.
    Import Physics (.phys)OnExperimental. Physics is work in progress; untick this for now.
    Phys File OverrideemptyExperimental. Only shown when Import Physics is on.

    What you get in the scene

    • Armature named <model>_Armature with bones bone_000, bone_001, … The M2 bone data (key bone id, flags, name CRC) is kept on each bone.
    • Geoset meshes, each carrying its geoset id and M2 material settings.
    • Actions named <model>_<Animation> (for example …_Stand, …_Walk_1), one per sequence, all kept with a fake user so none are lost on save. Global sequences get their own actions.
    • Empties for attachments and events, cameras, and the bounding box.
    TipThe add-on remembers the path of the imported .m2 in the scene. Export uses it to read back tables that have no Blender equivalent, so keep the original file where it was.

    Exporting

    Four ways to write a model, from a full standalone build to a byte-exact vertex patch.

    Choosing an export mode

    You want to…SettingsFiles written
    Build a complete model from whatever is in the sceneFormat: Chunked, New Model on (default).m2, 00.skin
    Replace an existing model's slot with your geometryNew Model off, Patch into M2 set.m2 and every skin LOD the target has
    Nudge vertices on an original model and change nothing elseSame as above, imported with Weld Seam Vertices off.m2 plus copies of the original skins
    Ship a new retail character with its own skeleton fileNew Model off, Full Custom on.m2, .skel, 00.skin
    Target a Wrath-era clientFormat: Flat MD20.m2 and a name-based .skin

    New Model (from scratch)

    The default. Builds a self-contained M2 from the meshes, armature and actions in the scene, with bones and animations embedded. Works on imported models and on rigs made entirely in Blender.

    1. Choose File › Export › WoW Model (.m2). Keep Format on Chunked MD21 (retail) and New Model (from scratch) ticked.
    2. Set Skin FileDataID to the id you will register the exported 00.skin under.
    3. Set Texture FileDataID as the fallback texture for materials that do not name their own. Materials configured in the M2 Material panel override it.
    4. Tick Force All Geosets Visible for creature or object style models. See geoset visibility.
    5. Click Export M2.

    How animations are picked up

    • Actions created by the importer are exported as the sequences they came from, keeping id, variation, flags, duration and blend times.
    • Actions you create yourself are matched by name: end the name with a WoW animation name and an optional variation number, such as MyRig_Stand, MyRig_Walk or MyRig_Attack1H_1.
    • With neither, the armature's active action is exported as Stand. With no action at all, a one-second static Stand is written so the model still loads.
    Materials fill themselves inWhen the scene came from an import, meshes without M2 material settings inherit the texture binding their geoset id had in the source model.

    Patch into an existing M2

    Use this to put your model on another model's slot. The target's structure (LOD count, skin file ids, extra chunks) is kept and only geometry is replaced.

    1. Untick New Model and leave Full Custom off.
    2. Set Patch into M2 (target slot) to the original .m2 you are replacing. If left blank, the file you imported is used.
    3. Optionally set Skin FileDataID, otherwise the target's ids are reused.
    4. Export. All skin LODs the target expects are written next to the .m2.

    In-place vertex patch. If the scene has exactly the same vertices as the target (import with Weld Seam Vertices off and do not add or delete geometry), only positions, normals and UVs are written back. Everything else stays byte-identical and the original skins are copied across. This is the safest way to reshape an existing model.

    Bone names matter herePatch and Full Custom read bones by the importer's bone_NNN names. For a rig from elsewhere, use New Model mode, which accepts any armature.

    Full Custom (.skel)

    Writes a mesh-only, single-LOD M2 plus a .skel carrying the skeleton and animations, the layout modern retail characters use. Choose this when you change meshes and re-animate a character.

    1. Untick New Model, tick Full Custom (write .skel).
    2. Fill in Skeleton FileDataID and Skin FileDataID. Both are required.
    3. Export, then register the .m2, .skel, 00.skin and textures under those ids.

    Geoset visibility warnings

    The game only draws a geoset with a non-zero id when something switches that group on (character customization, equipment, or creature geoset data). Meshes that keep ids inherited from a character import can therefore be invisible on a new model. Export warns you when it sees non-zero ids, and reports any geoset whose skin data will not draw, with details in the System Console.

    Fix it by ticking Force All Geosets Visible, which sets every id to 0, or by assigning correct ids in the M2 Geoset panel.

    Materials and textures

    The M2 Material panel controls how each material is textured and blended in game.

    M2 Material panel

    Select a mesh, open the M2 tab and expand M2 Material. The panel edits the active material. Changes apply immediately and are saved with the .blend.

    • Add M2 Material creates a new material with M2 settings on the active mesh.
    • Apply Material to Selected gives every other selected mesh the active object's material, settings included. Select the targets, then shift-click the source mesh last.

    Texture type

    Texture Type decides where the texture comes from. File (BLP) is a real file you name. Every other type means the client supplies this at runtime, and it only does so in the situation that type exists for.

    TypeUse for
    File (BLP)Your own texture. The normal choice for custom models.
    Skin (composited)Character body and most armor. The client bakes skin, underwear and gear together.
    Object SkinCloaks and item models textured from item data.
    Character Hair / Facial HairHair geosets that follow the character's hair color.
    Monster Skin 1–3Creature skins chosen by creature display data.
    EnvironmentReflection map for shiny surfaces.
    Weapon Blade / Handle, Guild types, othersSpecial slots filled by the client for items and tabards.
    Invisible mesh?A runtime type on a model the client does not bind it for resolves to no texture. Combined with Alpha Key blending, every pixel is discarded and the mesh disappears. Switch the material to File (BLP) and give it a texture.

    Texture by FileDataID

    With File (BLP) selected, enter the BLP's id in Texture FileDataID. It is written to the model's texture id table and is how retail clients find the file.

    Hardcoded texture path

    Texture Path bakes a file path into the model's texture record for that material, so the texture is tied to the geosets using it. Leave it empty to rely on the FileDataID alone. The FileDataID is still written alongside the path.

    1. Set Texture Type to File (BLP).
    2. Type or browse to the path in Texture Path.
    3. Export as usual. Two materials with the same FileDataID but different paths stay separate textures.
    The path is written exactly as typedThe game expects a game-style path such as creature\mymodel\mymodel_body.blp, not a location on your disk. If you pick a file with the browser button, edit the result into that form.

    Blend mode and opacity

    BlendResult
    OpaqueNo transparency.
    Alpha KeyHard cutout. Hair edges, foliage, fences.
    Alpha BlendSmooth transparency.
    No-Alpha AddAdditive, ignoring the alpha channel.
    Add (glow)Additive. Black becomes invisible; use for glows.

    Opacity below 1 fades the material and forces an alpha blend. Shader ID is written to the batch as is; leave it at 0 unless you know the shader you need.

    Geosets

    Geoset ids tell the game which mesh pieces to show for hair styles and equipment.

    How geoset ids work

    An id is group × 100 + variant. Id 0 is always drawn. Anything else is drawn only when its group and variant are enabled.

    GroupIdsControls
    00, 1–99Base body (0) and hairstyles
    1–31xx–3xxFacial hair
    4 / 54xx / 5xxGloves / boots
    77xxEars
    8 / 98xx / 9xxSleeves / leg cuffs
    10 / 1110xx / 11xxChest / pants
    12 / 1312xx / 13xxTabard / trousers or robe
    15 / 1815xx / 18xxCloak / belt

    M2 Geoset panel

    1. Select an imported geoset mesh. The panel shows its current id, group and variant.
    2. Pick a Group and Variant, or choose Custom id and type the full number. The mesh updates immediately and is renamed to …_geoset_NNNN.
    3. To set many meshes at once, select them all and click Apply to N Selected.

    For meshes you modelled yourself, select them and use Apply to N Selected to stamp an id.

    Bones and animation

    Inspect bone data, tune how animations blend in game, and re-pose a rig safely.

    M2 Bone panel

    Select the armature and click a bone in Edit or Pose mode. The panel shows the data the game uses to identify it: Key Bone (named slots such as Head, Jaw, ArmL, Root that the client looks up directly), Flags, Submesh and Name CRC. These values are preserved on export.

    Keyframe Pose + Apply Rest

    Changes the rest pose of a rig without breaking its animations.

    1. Select the armature and enter Pose mode.
    2. Rotate bones into the new default pose.
    3. In M2 Bone, click Keyframe Pose + Apply Rest (all actions).

    Every action that has no rotation keys for a posed bone receives a frame-0 key holding the new rotation, then the pose is applied as the rest pose.

    Save firstThis edits every action in the file.

    M2 Action panel and blend times

    With an armature selected, M2 Action shows the active action's animation id and name, variation, sequence index, duration and flags.

    Blend In (ms) and Blend Out (ms) set the cross-fade when the game switches to or from this animation. 0 makes the model snap from one animation to the next. Original game files use 150 in and 0 out for most animations.

    • Imported actions carry the values from the file and you can edit them in place.
    • For actions without stored values, click Edit Blend Times to add the fields. Untouched actions export with the 150 / 0 default.
    • Files whose blend times are all zero (written by early versions of this add-on) are repaired to the default on import.

    Naming your own actions

    New Model export recognises actions whose name ends in a WoW animation name, optionally followed by a variation number: Stand, Rig_Run, Rig_Attack1H_1, Rig_EmoteDance. A trailing _remap from retargeting tools is ignored. Variations of the same animation are linked and given equal play weight automatically.

    Bounding box and camera framing

    The M2_BoundingBox wireframe is the model's render bounds. The game frames portrait and character-screen cameras around its centre. Move, scale or edit its corners and export writes the new box. Raise it to make the camera look higher, lower it to look lower. Delete the object and bounds are computed from the vertices instead.

    Attachments, events and cameras

    Attachment and event empties are parented to their bones, so move them in the viewport to reposition weapon mounts, spell origins or footstep triggers. Imported cameras keep their target empty, clip distances, field of view and animation.

    Physics Coming soon

    Cloth, chain and jiggle physics with .phys import and export. In development, not ready to use yet.

    Work in progress

    Physics support is still being built. An M2 Physics panel and physics options appear in the add-on, but they are experimental: results are unreliable and files written by them may not behave correctly in game. Full documentation will be added here when the feature is ready.

    What is planned

    • Import a model's .phys file as an editable rigid-body rig.
    • One-click presets that set up cloth, chains and jiggle on selected bones.
    • Colliders, so simulated parts rest against the character.
    • A baked preview that plays the simulation on the skeleton inside Blender.
    • Export back to a .phys the game loads.

    In the meantime

    Models import, edit and export normally without physics. To keep experimental physics data out of your work:

    • On import, untick Import Physics (.phys).
    • On export, leave Phys FileDataID at 0. A .phys file is only written when the scene contains a Rigid Body World, so a scene without one exports no physics.

    Troubleshooting

    Common problems and where to look.

    Common problems

    SymptomLikely cause and fix
    Imported mesh is emptyNo .skin next to the .m2. Extract <name>00.skin into the same folder.
    No animations, or only someThe model stores them in .skel or .anim files that are missing, or Max Animations is limiting the import.
    Parts of the model are invisible in gameNon-zero geoset ids (see geoset visibility), or a runtime texture type with Alpha Key blending (see texture type).
    Model is untextured in gameA File (BLP) material has no FileDataID. Export warns about this. Set it in the panel or use Texture FileDataID at export.
    Animations snap instead of blendingBlend times are 0. Set them in M2 Action and re-export.
    Animations look wrong after scalingThe rig was scaled in Blender. Undo that and use Export Scale.
    Export fails in Patch or Full Custom modeBones are not named bone_NNN, or the source M2 cannot be found. Check the System Console for the paths that were tried.
