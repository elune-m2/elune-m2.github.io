    Documentation

    Every feature in Elune M2, grouped by where you find it in Blender, with the steps to use it.

    Getting started

    Install the add-on and learn where its tools live.

    Requirements

    • Blender 5.0 or newer. The add-on is packaged as a Blender extension.
    • Model files extracted from the game: the .m2 plus the files that sit beside it (.skin, and where the model has them .skel, .anim and .phys). Keep them in the same folder with their original names so the importer finds them.

    Install

    1. Download the add-on .zip. Do not unzip it.
    2. In Blender open Edit › Preferences › Get Extensions.
    3. Open the drop-down arrow in the top-right corner and choose Install from Disk…, then pick the zip.
    4. Make sure Elune M2 is ticked in the Add-ons list.

    Importing a model

    Bring an M2 into Blender as editable meshes, an armature, actions and helper objects.

    Basic import

    1. Choose File › Import › WoW Model (.m2). You can select several files at once.
    2. Leave Expansion on Auto-detect unless a file is misread.
    3. Adjust the options in the right-hand column (below), then click Import M2.

    The status bar reports the detected format, vertex and triangle counts, and how many animations and attachments were built. If it says no skin file found, the .skin is missing from the folder and the mesh will be empty.

    Import options

    OptionDefaultWhat it does
    ExpansionAuto-detectWhich parser reads the file. Override only if auto-detect guesses wrong.
    Import SkeletonOnBuilds an armature from the bones and skins the mesh to it. Animations, attachments and cameras need this.
    Split GeosetsOnEach geoset becomes its own mesh object named …_geoset_NNNN. Turn off for one merged mesh.
    Import AnimationsOnCreates one Blender Action per animation sequence.
    Import AttachmentsOnCreates an empty at each attachment point (weapon and effect mounts), parented to its bone.
    Import CamerasOnCreates a Blender camera for each M2 camera (portrait, character info) with its target, field of view and animation.
    Import Bounding BoxOnCreates the editable M2_CollisionBox and M2_BoundingBox wireframes. See Bounding boxes.
    Import EventsOnCreates an empty per event ($SHR, $FL0, …) and adds standard events the model lacks so sheathe, footstep, cast and breath triggers fire in game.
    Bone Tilt (deg)0Fans bones outward so they are easier to see and click. Animations are converted in and out automatically.
    Weld Seam VerticesOnMerges the duplicate vertices M2 stores along UV and normal seams into a connected mesh. Turn off only for the in-place vertex patch, which needs identical topology.
    Animation FPS30Frame rate used to convert millisecond keyframe times to frames.
    Max Animations0 (all)Caps how many clips are built. Characters can have 400+ sequences; lower this for a quick import.
    Mirror XOffFlips handedness. If you use it, use the same setting on export.
    Repair Stray WeightsOnA vertex bound to a bone none of its neighbours use takes its neighbours' weights. Retail files have the odd vertex bound to the root in the middle of a head part (a blood elf eye glow has one), which otherwise stays behind when the head moves.
    Normalize UV TilesOnShifts each UV island by whole tiles onto the 0–1 grid. Retail hair sits several tiles away from the origin; its texture wraps, so the model draws the same either way, but the UVs are far easier to edit on the grid. Only axes the texture wraps on are shifted.

    Phys File OverrideemptyExplicit path to a .phys file, used instead of the automatic search.

    What you get in the scene

    • Armature named <model>_Armature with bones bone_000, bone_001, … The M2 bone data (key bone id, flags, name CRC) is kept on each bone.
    • Geoset meshes, each carrying its geoset id and M2 material settings.
    • Actions named <model>_<Animation> (for example …_Stand, …_Walk_1), one per sequence, all kept with a fake user so none are lost on save. Global sequences get their own actions.
    • A <model>_phys collection holding the physics rig, if the model has one.
    • Empties for attachments and events, cameras on aim empties, and the two bounding boxes.
    TipThe add-on remembers the path of the imported .m2 in the scene. Export uses it to read back tables that have no Blender equivalent, so keep the original file where it was.

    Exporting

    Four ways to write a model, from a full standalone build to a byte-exact vertex patch.

    Choosing an export mode

    You want to…SettingsFiles written
    Build a complete model from whatever is in the sceneFormat: Chunked, New Model on (default).m2, 00.skin, physics if rigged
    Replace an existing model's slot with your geometryNew Model off, Patch into M2 set.m2 and every skin LOD the target has
    Nudge vertices on an original model and change nothing elseSame as above, imported with Weld Seam Vertices off.m2 plus copies of the original skins
    Ship a new retail character with its own skeleton fileNew Model off, Full Custom on.m2, .skel, 00.skin
    Target a Wrath-era clientFormat: Flat MD20.m2 and a name-based .skin

    New Model (from scratch)

    The default. Builds a self-contained M2 from the meshes, armature and actions in the scene, with bones and animations embedded. Works on imported models and on rigs made entirely in Blender.

    1. Choose File › Export › WoW Model (.m2). Keep Format on Chunked MD21 (retail) and New Model (from scratch) ticked.
    2. Set Skin FileDataID to the id you will register the exported 00.skin under.
    3. Set Texture FileDataID as the fallback texture for materials that do not name their own. Materials configured in the M2 Material panel override it.
    4. Tick Force All Geosets Visible for creature or object style models. See geoset visibility.
    5. Click Export M2.

    How animations are picked up

    • Actions created by the importer are exported as the sequences they came from, keeping id, variation, flags, duration and blend times.
    • Actions you create yourself are matched by name: end the name with a WoW animation name and an optional variation number, such as MyRig_Stand, MyRig_Walk or MyRig_Attack1H_1.
    • With neither, the armature's active action is exported as Stand. With no action at all, a one-second static Stand is written so the model still loads.
    Materials fill themselves inWhen the scene came from an import, meshes without M2 material settings inherit the texture binding their geoset id had in the source model.

    Patch into an existing M2

    Use this to put your model on another model's slot. The target's structure (LOD count, skin file ids, extra chunks) is kept and only geometry is replaced.

    1. Untick New Model and leave Full Custom off.
    2. Set Patch into M2 (target slot) to the original .m2 you are replacing. If left blank, the file you imported is used.
    3. Optionally set Skin FileDataID, otherwise the target's ids are reused.
    4. Export. All skin LODs the target expects are written next to the .m2.

    In-place vertex patch. If the scene has exactly the same vertices as the target (import with Weld Seam Vertices off and do not add or delete geometry), only positions, normals and UVs are written back. Everything else stays byte-identical and the original skins are copied across. This is the safest way to reshape an existing model.

    Bone names matter herePatch and Full Custom read bones by the importer's bone_NNN names. For a rig from elsewhere, use New Model mode, which accepts any armature.

    Full Custom (.skel)

    Writes a mesh-only, single-LOD M2 plus a .skel carrying the skeleton and animations, the layout modern retail characters use. Choose this when you change meshes and re-animate a character.

    1. Untick New Model, tick Full Custom (write .skel).
    2. Fill in Skeleton FileDataID and Skin FileDataID. Both are required.
    3. Export, then register the .m2, .skel, 00.skin and textures under those ids.

    Other export options

    Body Skin Texture FileDataIDConverts the client-composited body skin (texture type 1) into a fixed texture with this id. Use it when body geosets are invisible on a custom character. 0 leaves it composited.

    Geoset visibility warnings

    The game only draws a geoset with a non-zero id when something switches that group on (character customization, equipment, or creature geoset data). Meshes that keep ids inherited from a character import can therefore be invisible on a new model. Export warns you when it sees non-zero ids, and reports any geoset whose skin data will not draw, with details in the System Console.

    Fix it by ticking Force All Geosets Visible, which sets every id to 0, or by assigning correct ids in the M2 Geoset panel.

    Materials and textures

    The M2 Material panel controls how each material is textured and blended in game.

    M2 Material panel

    Select a mesh, open the M2 tab and expand M2 Material. The panel edits the active material. Changes apply immediately and are saved with the .blend.

    • Add M2 Material creates a new material with M2 settings on the active mesh.
    • Apply Material to Selected gives every other selected mesh the active object's material, settings included. Select the targets, then shift-click the source mesh last.

    Texture type

    Texture Type decides where the texture comes from. File (BLP) is a real file you name. Every other type means the client supplies this at runtime, and it only does so in the situation that type exists for.

    TypeUse for
    File (BLP)Your own texture. The normal choice for custom models.
    Skin (composited)Character body and most armor. The client bakes skin, underwear and gear together.
    Object SkinCloaks and item models textured from item data.
    Character Hair / Facial HairHair geosets that follow the character's hair color.
    Monster Skin 1–3Creature skins chosen by creature display data.
    EnvironmentReflection map for shiny surfaces.
    Character Eyes (19)The eyeballs. Filled from the eye-colour customization. Retail eye materials use two layers of this type with a multi-layer Shader ID.
    Character Jewelry (20), Secondary Skin / Hair / Armor (21–23)Customization slots added in Shadowlands: earrings, piercings, tattoos, second hair layers.
    Weapon Blade / Handle, Guild types, othersSpecial slots filled by the client for items and tabards.
    Invisible mesh?A runtime type on a model the client does not bind it for resolves to no texture. Combined with Alpha Key blending, every pixel is discarded and the mesh disappears. Switch the material to File (BLP) and give it a texture.

    Texture layers

    Some materials draw more than one texture: retail eyes and eye glow use two layers of the same texture with a two-layer Shader ID, and tabards use six. The panel edits the first layer, and shows Second Texture Layer with its own type and FileDataID when the material has one. Further layers are kept exactly as imported and noted as "+N more layers". Untick the second layer to export a single-layer material; when you do, set Shader ID to a single-layer value as well.

    Render data kept from the import

    Geosets whose material draws more than one texture layer (eyes, eye glow, tabards) carry a second UV map, UVMap2, that the second layer samples. It is imported alongside UVMap and written back on export; single-layer geosets have none. If you build a two-layer material on your own mesh, give it a UVMap2 or the second layer will sample nothing.

    Each imported material also remembers batch data that has no Blender control but that the game needs: the batch flags (0x10 on ordinary body batches, 0x80 on eye glow), which UV map each layer samples, and any texture transform on a layer. Eye glow on every retail character is a second texture layer scrolling on a looping global sequence; that transform, and the colour tracks some models use to tint or fade parts, are carried into the export unchanged, so glow, tints and fades survive a round trip. Materials you make from scratch get the retail defaults.

    Texture by FileDataID

    With File (BLP) selected, enter the BLP's id in Texture FileDataID. It is written to the model's texture id table and is how retail clients find the file.

    Hardcoded texture path

    Texture Path bakes a file path into the model's texture record for that material, so the texture is tied to the geosets using it. Leave it empty to rely on the FileDataID alone. The FileDataID is still written alongside the path.

    1. Set Texture Type to File (BLP).
    2. Type or browse to the path in Texture Path.
    3. Export as usual. Two materials with the same FileDataID but different paths stay separate textures.
    The path is written exactly as typedThe game expects a game-style path such as creature\mymodel\mymodel_body.blp, not a location on your disk. If you pick a file with the browser button, edit the result into that form.

    Geosets

    Geoset ids tell the game which mesh pieces to show for hair styles and equipment.

    How geoset ids work

    An id is group × 100 + variant. Id 0 is always drawn. Anything else is drawn only when its group and variant are enabled.

    1–31xx–3xxFacial hair

    M2 Geoset panel

    1. Select an imported geoset mesh. The panel shows its current id, group and variant.
    2. Pick a Group and Variant, or choose Custom id and type the full number. The mesh updates immediately and is renamed to …_geoset_NNNN.
    3. To set many meshes at once, select them all and click Apply to N Selected.

    For meshes you modelled yourself, select them and use Apply to N Selected to stamp an id.

    Bones and animation

    Inspect bone data, tune how animations blend in game, and re-pose a rig safely.

    M2 Bone panel

    Select the armature and click a bone in Edit or Pose mode. The panel shows the data the game uses to identify it: Key Bone (named slots such as Head, Jaw, ArmL, Root that the client looks up directly), Flags, Submesh and Name CRC. These values are preserved on export.

    Keyframe Pose + Apply Rest

    Changes the rest pose of a rig without breaking its animations.

    1. Select the armature and enter Pose mode.
    2. Rotate bones into the new default pose.
    3. In M2 Bone, click Keyframe Pose + Apply Rest (all actions).

    Every action that has no rotation keys for a posed bone receives a frame-0 key holding the new rotation, then the pose is applied as the rest pose.

    Save firstThis edits every action in the file.

    M2 Action panel and blend times

    With an armature selected, M2 Action shows the active action's animation id and name, variation, sequence index, duration and flags.

    Blend In (ms) and Blend Out (ms) set the cross-fade when the game switches to or from this animation. 0 makes the model snap from one animation to the next. Original game files use 150 in and 0 out for most animations.

    • Imported actions carry the values from the file and you can edit them in place.
    • For actions without stored values, click Edit Blend Times to add the fields. Untouched actions export with the 150 / 0 default.
    • Files whose blend times are all zero (written by early versions of this add-on) are repaired to the default on import.

    Naming your own actions

    New Model export recognises actions whose name ends in a WoW animation name, optionally followed by a variation number: Stand, Rig_Run, Rig_Attack1H_1, Rig_EmoteDance. A trailing _remap from retargeting tools is ignored. Variations of the same animation are linked and given equal play weight automatically.

    Bounding boxes and camera framing

    Import creates two editable wireframe boxes, both read straight from the file:

    • M2_CollisionBox: the collision box. On retail characters this is body-sized (about 0.3 m wide and 2 m tall), and it is what the character and transmog screens frame their camera from. If the model looks far away or off-centre there, this is the box to move or resize.
    • M2_BoundingBox: the render bounds. Retail characters store a very large box here (it covers every animation) so the model is never culled mid-move. Leave it alone unless parts of the model vanish at the edge of the screen.

    Move, scale or edit either box and export writes the new values. Boxes you do not touch are written back exactly as the file had them, including their sphere radii. Delete a box object and that box is computed from the vertices instead.

    Attachments, events and cameras

    Attachment and event empties are parented to their bones, so move them in the viewport to reposition weapon mounts, spell origins or footstep triggers.

    Each M2 camera (portrait, character info) is imported as a camera riding on a small aim empty (…_camrig_…) that points at a target empty, with world Z up, plus its clip distances, field of view and animation. Move the aim empty to move the camera and the target empty to change what it looks at; the camera object's own Z rotation is the roll. Export writes them back exactly, including the camera lookup table the client uses to pick the character-screen camera.

    Physics

    Give a model cloth, chains and soft body parts that move in game: rig bones in one click, preview the motion on the skeleton in Blender, tune it, and export it inside the model.

    Quick start

    The whole workflow, from a retail model to a moving one in game.

    1. Import the original model. File › Import › WoW Model (.m2) with the defaults. Start from the retail file, not from an earlier export of your own.
    2. Open the panel. Press N in the 3D viewport, pick the M2 tab and expand M2 Physics. If the model already has physics, the top of the panel lists its rig with body and joint counts.
    3. Select the bones to animate. Click the armature, enter Pose Mode and select the bones. For a hanging chain (cloak, ponytail, tassel) select every bone of the chain but not the bone it hangs from. For a soft body part select just that part's bone or bones.
    4. Click a preset under Build: Cloth, Chain, Jiggle or Soft Body. The status bar reports how many bodies were made. Bodies appear on the bones, sized to the mesh they deform, with joint arrows leading to the anchor they hang from.
    5. Preview. Optionally assign a Walk or Run action to the armature first, then click Start Preview. The timeline plays and the bones follow their simulated bodies. Click Stop Preview when done.
    6. Tune. Select a joint or a body and adjust it (see Tuning the motion). Preview again.
    7. Check and export. Click Check Rig, then export the model as usual (File › Export › WoW Model (.m2), New Model). The physics is embedded in the .m2; the status bar confirms it, for example Physics embedded: 3 bodies, 2 joints; bone flag 0x400 on bones 23, 26.
    8. Test in game, then come back and adjust Stiffness, Cone Angle or Drag if it moves too much or too little.

    How WoW physics works

    A physics rig is made of bodies and joints. Each body is attached to one bone and built from simple shapes (spheres, capsules, boxes). Joints link bodies and decide how they may move. In game the simulated bodies drive their bones, so the mesh follows.

    Body typeColourWhat it does
    Root AnchorAmberFollows its bone; chains hang from it. Written first in the file.
    DynamicBlueSimulated. Swings, bounces and drives its bone.
    Anchor / ColliderGreenAlso follows its bone. Use it as the anchor for a chain hanging from a different bone, or as a collider that dynamic bodies bounce off. Retail rigs have several.

    The rig lives in a collection named <model>_phys. Bodies and joints ride on the skeleton, so they stay in place when you pose, animate or move the character; only while a preview runs do the dynamic bodies move on their own.

    The panel, top to bottom

    The M2 Physics panel changes with what you have selected. Its fixed parts, in order:

    PartWhat it shows or does
    Rig statusEvery rig in the scene with its body and joint counts. The arrow button (Show Rig) unhides and selects that rig and frames it in the viewport. A rig made by an early build shows an "Old-format rig" warning: delete that collection and re-import the physics or rebuild it.
    Selected bodyAppears when a body is selected: type, bone, mass, drag, its shapes, Fit to Mesh and Make Root Anchor. See Editing a body.
    Selected jointAppears when a joint is selected: type, the two bodies it links, and its limits and spring. See Tuning the motion.
    BuildThe presets (in Pose Mode), Add Body / Add Collider, the shape and radius for new bodies, the joint type for Connect Selected, and Delete Selected.
    PreviewStart Preview / Stop Preview, Bodies Collide With Each Other, and the solver's Substeps and Solver Iterations.
    ExportFormat Version, Check Rig, Import .phys / Export .phys, Remove Physics Rig, and the physics build number of the add-on (quote it when reporting a problem).

    Importing physics

    With Import Physics (.phys) ticked, the importer builds the rig automatically. It looks for physics data in this order:

    1. The file set in Phys File Override, if any.
    2. The physics embedded in the .m2. This is how retail models carry it, so most models need no extra file.
    3. A <name>.phys file beside the model, or the only .phys in the folder.

    All format versions from 0 to 6 are read. Anything the add-on does not edit is kept, so a rig you import and export without changing is written back byte for byte.

    To load physics onto a model already in the scene, select its armature and use Import .phys in the panel. It replaces the armature's current rig.

    Rigging bones in one click

    1. Select the armature and enter Pose Mode.
    2. Select the bones that should move. For a chain (cloak, ponytail), select the whole chain but not the bone it hangs from. For a soft body part, select just that bone.
    3. Under Build, click a preset.

    Each selected bone gets a body fitted to the mesh it deforms, joined to the body above it. A chain bone gets a capsule along the chain; a single bone such as a breast or an ear gets a shape sitting on the flesh itself. If the rig has no root yet, one is created on the chain's parent bone; a chain hanging from a different bone gets an anchor on that bone.

    PresetShapeFeelGood forModelled on
    ClothCapsuleSwings in a 40° cone with a gentle 1 Hz pull back to restCloaks, tabards, skirts, hairStorm gryphon reins
    ChainCapsuleWide 60° swing, ±25° twist, some dragChains, pendants, hanging gearNerubian leather belt
    JiggleCapsule45° cone held by a firm 3 Hz spring, heavy dragEars, tails, small dangling partsNetherwing drake dangles
    Soft BodySphereTight 12° cone, 3 Hz spring, heavy drag: barely moves at idle, nudges with motionChest, belly, thighsDrake dangles, tightened

    All presets use shoulder joints, the joint type retail uses for hanging parts and the only one confirmed to work on a player model in game.

    Presets are re-runnableClicking a preset on bones that already have bodies converts them in place: joints switch type and values, bodies take the preset's numbers, nothing is duplicated. Use this to switch a part from Jiggle to Soft Body, or to refresh a rig after updating the add-on. Shapes you moved or resized by hand are kept.

    Tuning the motion

    Select a joint (the small arrows where a body meets its anchor) for the first four settings, and the body itself for the last two.

    SettingOnEffect
    Cone AngleJointHow far the part is allowed to swing away from rest, in degrees. The main "how much can it move" control. 12° is subtle, 25° is visibly bouncy, 45°+ flaps.
    Stiffness (Hz)JointThe spring that pulls the part back to rest. Higher holds firmer against wind, movement and collisions; lower swings bigger and softer. Retail uses 1 to 3. Below about 1.5 the part starts drifting with the wind at idle; at 0 nothing holds it at all.
    Stiffness DampingJointHow the spring settles. 0.7 settles in about one bounce; 0.4 wobbles two or three times; 1 stops without any overshoot.
    Twist Min / MaxJointRotation about the bone's own axis, in degrees. Not part of bounce; keep it small.
    DragBodyAir resistance. Higher calms everything and settles sooner; lower lets movement carry more momentum into the bounce.
    MassBodyTotal weight. The spring is scaled with it, so on its own it changes little; it matters for how bodies push each other.

    Two starting points beyond the presets:

    • More bounce: cone 22, stiffness 2, damping 0.45, drag 3.
    • Hold still against wind or armour: cone 8, stiffness 5, damping 0.7, drag 8.
    Wind and armourThe game applies wind to physics bodies, and bodies on different pieces (a belt with physics, a chest piece) share one simulation with the character's, so they push each other. Both are answered by Stiffness: a firm spring turns a shove into a nudge. If a body overlaps armour at rest, reduce its radius a little.

    Editing a body

    Select a body to see its settings: Type, Bone, Mass, Drag, and each shape's geometry (a capsule's Start, End and Radius; a sphere's centre and radius) plus Friction and Bounciness.

    • Fit to Mesh puts the body back on its bone and refits its shape to the vertices that bone deforms.
    • Add Shape gives a body more than one shape; the X beside a shape removes it.
    • Make Root Anchor makes this body the one written first; the previous root becomes an ordinary anchor.
    Edit in the viewport tooMove, rotate or scale a body like any object; export measures the rig as it stands and bakes that into the file. Joints can be moved and rotated the same way: the joint sits at the pivot and its blue Z arrow is the axis the part swings around.

    Building by hand

    • Add Body puts a dynamic body on the active pose bone; Add Collider adds an anchor. The shape and radius come from the two fields below; a radius of 0 fits one from the mesh or bone.
    • Connect Selected joins two selected bodies with the joint type chosen beside it. Select the parent first and the child last.
    • Delete Selected removes the selected bodies (with their joints) and any selected joints. Remove Physics Rig deletes the whole rig to start over.
    Joint typeMovementStatus
    ShoulderSwings within a cone about the Z axis, twists within limits, spring back to restConfirmed working in game. Used by all presets.
    SphericalPivots freely about the pointRead and written; not tested in game.
    WeldRigid, or a rotational spring above 0 HzDid not work on a player model in testing. Retail uses it on cloth items only.
    Revolute / Prismatic / DistanceHinge / slider / tetherRead and written from the spec; preview approximate; untested in game.

    Previewing the motion

    1. Optional: assign a Walk or Run action to the armature to see the rig react to movement.
    2. Click Start Preview. The timeline plays, the rig is simulated, and the simulated bones follow their bodies.
    3. Click Stop Preview to rewind and put the skeleton back. Any edit to the rig stops the preview automatically.

    Bodies Collide With Each Other lets simulated bodies hit one another; it is off by default because side-by-side strips are steadier without it. If small pieces jitter or pass through colliders, raise Substeps.

    How close is the preview?The rig's structure, shapes, masses and joint limits are exact. The motion is Blender's solver, not the game's, and the game adds wind, so treat the preview as a guide and fine-tune Stiffness and Drag in game.

    Exporting physics

    Exporting the model exports its rig: the physics is embedded in the .m2, exactly as retail models carry it, so there is nothing extra to register. The export dialog notes "Physics rig found" when a rig is present, and the status bar afterwards reports what was written, for example Physics embedded: 3 bodies, 2 joints; bone flag 0x400 on bones 23, 26.

    The exporter also does two things the game requires: it flags the model as having physics, and it gives every simulated bone bone flag 0x400 (and removes 0x200, so the bone's keyframes no longer override the simulation). A <name>.phys copy is written beside the model for reference.

    Physics is written by New Model and Full Custom exports. Patch mode keeps the target model's own physics and warns that the scene's rig was not written.

    Before exporting, click Check Rig. It reports problems that would break the rig in game: no anchor, a body without a bone, two bodies driving the same bone, or a body joined to nothing. Export .phys writes the rig on its own as a file.

    Rigs you build are written as format version 6, the version every retail character and mount rig uses. Imported rigs keep the version they came with; Format Version in the panel changes it. If a rig was made with an earlier build of the add-on, set it to 6 and re-click its preset before exporting.

    Retarget M2I

    Bring meshes edited through M2Mod back onto an Elune-imported M2 rig, with the geoset settings, materials and names restored.

    What M2I is

    .m2i is the mesh-exchange format of M2Mod, a separate World of Warcraft model tool with its own Blender add-on. An M2I round trip keeps the skeleton and the meshes, but it knows nothing about this add-on's data: bone names come back as M2Mod's own names, and the meshes arrive without geoset ids, material settings, batch flags, second UV sets or the m2_* properties the exporter needs. The Retarget M2I panel (3D Viewport sidebar, M2 tab) moves those meshes onto the rig you imported with Elune and copies everything back from the geosets they replace.

    Workflow

    1. Import the original M2 with Elune (File › Import › WoW M2). This is the M2 rig: the reference for bone names, geoset settings and materials. Import its animations too if you want them in the export.
    2. Import the .m2i into the same scene with the M2Mod add-on. This is the M2I rig, with the edited meshes as its children.
    3. Rotate the M2I skeleton onto the M2 skeleton. M2Mod imports with a different orientation. Select the M2I armature object and rotate it (object mode, not pose mode) until its bones lie over the M2 rig's bones. The tool keeps every mesh exactly where it sits in the scene and compares shapes by position, so a rig that faces the wrong way ends up with meshes in the wrong place and no geoset matches. Zoom in on the head and hands to confirm the two skeletons coincide.
    4. Pick the rigs. Open Retarget M2I, set M2 Rig and M2I Rig, or select both armatures and click Use Selected Armatures; the armature that owns geoset meshes becomes the M2 rig.
    5. Click Retarget Meshes onto M2 Rig. The status bar and the System Console report what was matched.
    6. Clean up the scene (see below), then export as usual.

    What the tool does

    1. Bones are paired by order (bone 1 with bone 1, and so on, which is how M2Mod keeps them) and the M2I bones are renamed to the M2 names. If the two rigs do not have the same number of bones the tool pairs them by rest position instead and says so in the console. Vertex groups and bone parents follow the rename; a group that already had the new name is merged into it.
    2. Meshes parented under the M2I rig, or bound to it only by an armature modifier, are moved under the M2 rig with their world transform kept and their armature modifier pointed at it.
    3. Each moved mesh is paired with the geoset it replaces (see Match Meshes) and takes over that geoset's object name and mesh name, every m2_* property (geoset id, order, centre bone, and so on), the material slots with their per-face assignment, and any UV set it lacks, such as UVMap2 for eye-glow layers.
    4. Vertex groups that still name no M2 bone are re-pointed by the rest position of the bone they belonged to; a mesh whose group names exist nowhere any more takes the replaced geoset's weights by vertex position. Stray weights (a vertex bound to a bone none of its neighbours use, like retail's root-bound eye-glow vertex, or a vertex with no weight at all) are re-weighted from their neighbours.
    5. The replaced geoset meshes are deleted and the empty M2I armature removed, so the exporter sees one skeleton.

    Panel options

    OptionMeaning
    Match MeshesBy name, then shape (default): a mesh named like a geoset, suffixes such as .001 ignored, takes that geoset; the rest are paired by geometry. By order: meshes in name order against geosets in their M2 order; use it when names and shapes both changed and the M2I rig carries the full set. By name and By shape use one rule only.
    Shape ToleranceLargest mean vertex distance (model units) for two meshes to count as the same shape. Raise it a little for meshes that were only smoothed or nudged.
    Bone ToleranceLargest head distance accepted as the same bone when bones or vertex groups have to be found by position.
    Take Over NamesThe converted mesh gets the geoset's name; the original gets a .replaced suffix before it is removed.
    Replaced GeosetsDelete (default), Hide or Keep the originals. Hidden meshes still export unless you export with Selected Only.
    Remove M2I RigDelete the M2I armature once nothing is parented to it.
    Guess Lost Groups From WeightsLast resort for a vertex group whose bone exists on no armature: it goes to the M2 bone nearest the group's weighted centre.
    Copy Missing UV SetsTransfers UV sets the replaced geoset has and the new mesh lacks.
    Repair Stray WeightsRe-weights vertices that share no bone with their neighbours or carry no weight.
    Fix Vertex Groups by Bone PositionRuns the vertex-group repair alone on the selected meshes (or all meshes of the M2 rig when nothing is selected). Use it on meshes that were moved onto the rig by hand.

    Cleaning up after the conversion

    The exporter reads every object in the scene, so whatever the M2Mod import brought along besides the meshes has to go, or it is exported twice or in place of the real thing. After a successful retarget, check the Outliner for:

    RemoveKeep (created by the Elune import)
    Attachment empties from the M2I import. The exporter rebuilds the attachment table from every attachment object it finds, so duplicates or differently placed copies corrupt the table.The Elune attachment empties named <model>_attach_<name>, carrying the m2_att_id property.
    Cameras and camera targets from the M2I import; a second portrait or character-select camera makes the client pick the wrong one.The Elune camera rigs <model>_camrig_<label> with their camera and <model>_camtarget_<label> target.
    Any root or helper empty the M2I import created, and the M2I armature itself if Remove M2I Rig was off.The event markers <model>_event_<id>, the M2_BoundingBox and M2_CollisionBox helpers, and the physics rig collection if there is one.
    Meshes the report listed as unmatched that you do not want as new geosets. An unmatched mesh has no geoset id and exports as geoset 0 with a default material.Every mesh that took over a geoset name, and any geoset the M2I file did not carry (they were never replaced).
    Unused materials and images the M2I import added (File › Clean Up › Purge Unused Data once the objects are gone).The materials of the M2 import; the converted meshes reference them now.

    Then look at the report line: it lists unmatched meshes, unmatched bones and vertex groups that still name no M2 bone. Fix those before exporting; a vertex group with a foreign name exports as bone 0.

    Troubleshooting

    SymptomLikely cause and fix
    Every mesh is reported unmatchedThe M2I skeleton was not rotated onto the M2 skeleton, or the meshes were scaled. Undo the retarget, align the armature objects (their bones must overlap) and run again. If the meshes were heavily edited, switch Match Meshes to By order.
    Meshes matched but kept their old namesTake Over Names was off, or the mesh matched nothing. Names only carry over with a match.
    Vertex groups still carry M2Mod bone namesRun Fix Vertex Groups by Bone Position on the meshes. Leave the M2I armature (or a copy of it) in the file while doing so: the tool looks the old names up on any armature to find where each bone stood.
    Eye glow lost its animation after exportThe glow layers sample UVMap2, which M2I drops. Keep Copy Missing UV Sets on; it is restored from the replaced geoset.
    Mesh deforms wrongly in one spot, or a vertex stays behindA stray or unweighted vertex. Keep Repair Stray Weights on, or run Fix Vertex Groups by Bone Position.
    Export has doubled attachments or the wrong cameraLeftover M2I attachment empties or cameras. See cleaning up.

    Common problems and where to look.

    Common problems

    SymptomLikely cause and fix
    Imported mesh is emptyNo .skin next to the .m2. Extract <name>00.skin into the same folder.
    No animations, or only someThe model stores them in .skel or .anim files that are missing, or Max Animations is limiting the import.

    The game crashes (ERROR #132, access violation) on the character screen or when the model loadsThe M2 was exported with an earlier build that copied the retail "animations live in .anim / .skel files" header bits onto an embedded model.     Customization pieces (demon hunter horns and blindfolds, worgen transformation arms) are white / untextured in gameThe M2 was exported with an earlier build that left the texture-type lookup (textureIndicesById) empty, so the client could not swap the replaceable skin texture in for those geosets.     Animations look wrong after scalingThe rig was scaled in Blender. Undo that and use Export Scale.
    The model imports without a physics rigThe model may simply have none. Otherwise check that Import Physics and Import Skeleton were both ticked, and look for [phys] lines in the System Console.
    Export says "Physics NOT exported"The rig failed its check. Run Check Rig in the M2 Physics panel and fix what it lists.
    Physics shows in game but parts sit on the floor or driftThe rig was built with an early add-on build. Re-click the preset on the same bones (it converts them in place), set Format Version to 6, and export again.
    Parts wander in the wind or get shoved by armourRaise Stiffness (Hz) on the joints and Drag on the bodies. See Tuning the motion.
    The panel shows "Old-format rig"The rig was made by an earlier version of the add-on. Delete that collection and re-import the model's physics, or rebuild it with the presets.
    Preview jitters or pieces fall through collidersRaise Substeps in the Preview box. Very thin or tiny shapes need more.
    Meshes brought back from M2Mod export without geoset ids, materials or namesDo not export them as they arrive: run Retarget M2I so they take over the settings of the geosets they replace, then clean up the scene as that section describes.
    Export fails in Patch or Full Custom modeBones are not named bone_NNN, or the source M2 cannot be found. Check the System Console for the paths that were tried.
